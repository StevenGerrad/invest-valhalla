# 采集存储设计

## 暂缓采用 PostgreSQL 的原因

作出存储选择时，采集范围是单个 B 站博主，涉及的视频不到 2,000 条，现有资料以字幕文本为主。按作者目录和视频 ID 即可直接定位本地文件，现有布局能满足当前的读写和回查需求。

本期沿用本地文件存储，省去数据库接入、历史资料迁移与日常维护。后续有新的查询或存储需求时，再评估是否切换到 PostgreSQL。

## PostgreSQL 备选方案

采用单表保存采集资料。同一来源的原始稿和 Agent 优化稿分别保存为 `raw` 和 `optimized` 两行，正文均写入 `content`。尚未生成优化稿时只保存原始稿。

### 字段草案

| 字段 | 类型 | 用途 |
|---|---|---|
| `id` | BIGINT | 本行的自增主键。同一份稿件更新时保留原有 ID。 |
| `created_at` | TIMESTAMPTZ | 此行首次写入数据库的时间。更新时保留。 |
| `updated_at` | TIMESTAMPTZ | 此行最后一次修改的时间。首次写入时与创建时间相同。 |
| `platform` | VARCHAR(50) | 来源平台枚举成员的字符串值，例如 `bilibili`。 |
| `source_key` | VARCHAR(128) | 平台内容标识，例如 BV 号。平台内不同内容类型若共用数字 ID，可用带前缀的键，如 `answer:123`。 |
| `source_url` | VARCHAR(2048) | 可直接打开原始内容的地址。地址未知时为空。 |
| `author_id` | BIGINT | 作者的本地数字人 ID。未归属到已登记作者时为空。 |
| `author_name` | VARCHAR(100) | 采集时平台显示的作者名称。来源未提供名称时为空。 |
| `title` | VARCHAR(200) | 原始内容标题。来源未提供标题时为空。 |
| `content_type` | VARCHAR(50) | 资料的内容类型，例如字幕资料使用 `subtitle`。 |
| `variant` | VARCHAR(32) | 稿件类型。`raw` 表示原始稿，`optimized` 表示 Agent 优化稿。 |
| `status` | VARCHAR(32) | 资料的当前状态，由采集服务按业务约定填写。 |
| `published_at` | TIMESTAMPTZ | 平台公布的内容发布时间。未知时为空。 |
| `content` | JSONB | 本行稿件的完整内容。字幕保存为带时间的片段数组，其他资料按自己的内容结构保存。 |
| `metadata` | JSONB | 保存少量来源扩展信息，如播放量、来源声明的更新时点和导入方式。 |
| `content_hash` | BYTEA | 当前稿件内容的哈希值，用于判断内容变化及重复导入。 |

以 B 站字幕为例，两份稿件各自保存一个有序片段数组。每个片段记录 `start_seconds`、`end_seconds` 和 `text`，还可附带标题和关键词。两份稿件使用同一条媒体时间轴，可以独立调整片段边界。

### 更新与追溯草案

- 以 `platform + source_key` 归集同一来源的两份稿件，以 `platform + source_key + variant` 唯一定位其中一行。稿件或其状态更新时，保留该行 ID 并写入 `updated_at`。
- 未来的存储实现按来源归集两行，根据 `content_type` 组装具体的资料子类。字幕资料组装为 `SubtitleMaterialEntity`，原始稿行的 ID 对应资料实体 ID。
- 分别对每行 `content` 计算 `content_hash`。重复导入时，使用同一哈希算法和序列化规则比较稿件内容。
- 证据记录被引用稿件的行 ID、当时的内容哈希及引用位置。字幕引用可记录起止时间，正文引用可记录数组项下标和段落内字符区间。需要复核历史输出时，使用当次引用的稿件快照。
- 训练和推理的知识依赖、证据快照和可视化关系由数字人模块记录。历史评测以当次保留的快照为准。

### 已有资料迁移草案

1. 按原账号目录读取 `index.json`、原始 SRT 文件和已有的纠错结果。将两种字幕文件转换为同一种片段结构，分别写入 `raw` 行和可选的 `optimized` 行。`author_id` 使用该平台账号对应的本地数字人 ID。
2. 使用 `published_ts` 填写平台发布时间。每行首次写入时将创建时间和修改时间设为入库时间。重复导入按平台、内容标识和 `variant` 匹配已有记录，仅更新有变化的行。
3. 先试导少量样本，核对行数、字幕原文、纠错结果与随机引用时间点，再导入全量。保留旧目录供核对。

### 建表与索引 SQL 草案

```sql
-- 每条来源内容按稿件类型分别保存。账号与采集范围由本地配置管理。
CREATE SCHEMA ingestion;

CREATE TABLE ingestion.source_content (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_at timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP,
    platform varchar(50) NOT NULL,
    source_key varchar(128) NOT NULL,
    source_url varchar(2048),
    author_id bigint,
    author_name varchar(100),
    title varchar(200),
    content_type varchar(50) NOT NULL,
    variant varchar(32) NOT NULL CHECK (variant IN ('raw', 'optimized')),
    status varchar(32) NOT NULL,
    published_at timestamptz,
    content jsonb NOT NULL
        CHECK (jsonb_typeof(content) IN ('string', 'object', 'array')),
    metadata jsonb NOT NULL DEFAULT '{}'::jsonb
        CHECK (jsonb_typeof(metadata) = 'object'),
    content_hash bytea NOT NULL,
    UNIQUE (platform, source_key, variant)
);

-- 按本地作者 ID 跨平台查询资料，按平台发布时间排序。
CREATE INDEX source_content_author_timeline_index
    ON ingestion.source_content (author_id, published_at DESC);
```
