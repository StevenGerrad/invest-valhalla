# 数字人 Agent 相关项目调研

2026-11-27 · 相关工作调研 1/4

## 我们想问什么

- 已经有人把一个 B 站财经博主几年的视频变成可对话、可检索的专家了吗？他们具体做到了哪一步？
- 哪些人公开了从字幕到观点、案例和研究方法的过程？哪些只给了一个现成的 Skill 或一个产品页面？
- 有没有人让系统只读这个人的过去，再用**这个人后来真的说过的话**验证？有没有人把结果一层层连回原文？
- 如果 Valhalla 做成开源项目，哪些可以直接借，哪些差异还需要我们用实验来证明？

## 1. 范围和结论

Valhalla 首期围绕**同一位证券投资博主**，用他按时间发布的视频和文章，学习他公开谈过的观点以及常用的分析方法。模型权重冻结。系统回答历史问题时能跳回出处，分析新案例时能说明它用了什么方法。评测尽量按真实发表顺序，用这个人后来实际说过的话核对。

本篇补查论文正文、公开仓库、评测记录和官方产品说明。**公开代码、可下载数据、可核对原话和能复跑完整评测是四件不同的事。** 下文注明哪些属于作者报告，未独立运行第三方系统。已有工作覆盖多项单独能力。公开材料中，暂未核实一套同时把**单个真实中文证券作者、长视频论证、逐期先测后入库、逐项出处和可复跑实现**接在一起的项目。这是本次检索范围内的判断。

综述 *Two Tales of Persona in LLMs* 区分了让模型呈现指定人物与让系统适应用户偏好。Valhalla 的重点是前者，且范围限定为作者的公开证券分析。角色扮演评测综述则有助于把观点、知识和表达分开看。两篇综述用于确定比较项，下文判断仍以各项目的一手材料为准。 [Two Tales of Persona](https://aclanthology.org/2024.findings-emnlp.969/) · [角色扮演评测综述](https://arxiv.org/abs/2502.13012)

### 已有人怎么验证一个 Skill？

芒格 Skill 的公开报告用同一 Sonnet 模型比较新版、旧版和无 Skill。两道开放任务新版得 9、8，旧版 5、4，无 Skill 得 5、4.5。四道封存题满分 8，新版 4，另两组各 3，项目按自己的规则判为打平。每组只跑一次，开放任务评分方能看到案例库。实验用本人公开材料作对照，封存并未按其真实发言时间逐期推进。它的价值在于公布了题、答案、意见分歧和失败，不只公布一个综合分。 [芒格逐题报告](https://github.com/alchaincyf/munger-skill/blob/main/FIDELITY.md)

## 4. 产品可以参考什么

**Talk with Lex** 公开了从转录、关键词与向量检索，到每段说话人和秒数的实现。**Ask Huberman Lab** 展示专业内容中的出处与回听体验。**Berkshire Archive** 适合参考按年份、信件、会议查公开投资思想。**NotebookLM** 和 **Delphi** 分别展示选定来源内问答，以及多渠道内容接入与引用配置。**AlphaSense/Tegus** 展示怎样按公司、报告期和访谈看变化。产品文档能够支持这些交互判断，完整后台数据结构、标准测试集与复现实验未必公开。 [Talk with Lex](https://github.com/meilisearch/demo-talk-with-lex) · [Huberman Lab](https://ai.hubermanlab.com/support) · [Berkshire Archive](https://berkshireletters.com/ask/) · [NotebookLM](https://support.google.com/notebooklm/answer/16215270) · [Delphi](https://help.delphi.co/articles/16041852-add-knowledge-train-mind) · [AlphaSense](https://help.alpha-sense.com/hc/en-us/articles/42282785005587-How-to-Analyze-Earnings-Documents)

## 5. 如何把相似项目变成有用的对照

1. **与 Quant_Blibili 比资料和规则。** 锁定各自从原文到规则的过程。选一条规则，检查引用是否能打开、条件是否保存、又来了一个反例时会怎样更新。
2. **与已有财经 Skill 比使用方式。** 让同一模型用等量信息跑静态 Skill、普通 RAG、加版本化研究框架三组。保留沿用旧观点这一简单组，看更复杂的方法有没有带来自己的增益。
3. **借 MILA 的时间限制，与 Finer 的审计页面做两套检查。** 先证明晚期资料没有被提前使用，再逐条验引用是否支持分数和回答。最后用另一个同领域作者检验能否移植。

当前可以对外解释**我们要证明什么**。等公开了基线、每题原文、时点检查及失败样例，再说明**已经比什么好、好在哪里**。与另外三篇相互参照：[数字人的知识组织](261128_数字人Agent组织形式调研.md) · [评测与滚动测试](261128_数字人Agent评测调研.md) · [全过程追溯与可视化](261128_数字人Agent迭代追溯与可视化调研.md)。
