# 项目代码规范

## 注释与文档字符串

- 文档字符串的说明正文和代码注释使用中文。代码标识符使用英文，API 名称、字段名及通用缩写保留原文。
- 每个类都应有文档字符串，说明承担的职责以及与调用方或其他模块的边界。数据类说明它表达的内容和适用范围。
- 每个函数和方法都应有文档字符串，包括私有辅助函数和测试方法。首行概述用途，正文记录需要特别说明的行为。统一使用 Sphinx 的 reStructuredText 字段 `:param name:`、`:returns:`、`:raises ErrorType:` 标记参数、返回值和调用方需要处理的异常。字段标记及参数名使用英文，说明使用中文。参数按签名顺序列出，注明影响行为的单位、默认值及可空含义。省略 `self`、`cls` 和无值返回的 `:returns:`。类型以签名中的类型标注为准。 [PEP 257](https://peps.python.org/pep-0257/) · [Sphinx 字段说明](https://www.sphinx-doc.org/en/master/usage/domains/python.html#info-field-lists)
- 在方法内的关键代码块旁用中文注释说明处理原因、触发条件和结果。外部数据格式差异、配置优先级、状态转换、失败恢复和持久化等细节应写到足以让评审者理解实现取舍。测试注释说明用例意图和容易误读的数据，行为变化时同步更新注释。

### 在 PyCharm 中生成和检查

1. 打开 `Settings → Tools → Python Integrated Tools`，将 `Docstring format` 设置为 `reStructuredText`。
2. 在函数或方法体首行输入三引号后按回车，让 PyCharm 根据签名生成文档字符串骨架。按项目规范补写中文说明，并补充编辑器无法判断的返回含义、异常和特殊行为。
3. 使用 `Quick Documentation` 查看渲染效果。修改函数签名后，检查参数字段与签名是否一致，再提交代码。 [PyCharm 文档字符串设置](https://www.jetbrains.com/help/pycharm/settings-tools-python-integrated-tools.html)

## 模块与实现

- 按[系统架构划分](系统架构划分.md)分配职责。相关逻辑保留在拥有该职责的模块内，跨模块通过公开接口和明确的数据类型调用。第三方 SDK、协议和格式转换细节由接入模块封装。
- 保持依赖方向清晰，避免循环依赖。优先复用现有契约与实现，在确有多个实现或需要隔离外部依赖时抽象接口。
- 保持类与方法职责集中，使用领域术语命名。外部调用、文件写入及失败恢复应有清晰边界，调用方可以判断结果是否完整。

## 单元测试

- 单元测试集中在所属一级模块的 `test/` 下，沿用被测源码的相对路径。例如 `integration/fetcher/bilibili/client.py` 对应 `integration/test/fetcher/bilibili/test_client.py`。
- 测试文件按可验证的职责组织，相关用例可以放在同一文件。模拟网络和第三方服务，文件测试使用临时目录。真实服务验证与跨模块流程测试在有实际需求时独立运行。
- 使用 `unittest` 执行测试。递归枚举模块级 `test/` 下的 `test_*.py` 文件，将路径传给 `unittest`，测试目录可以省略 `__init__.py`。通过打包规则将模块级测试目录排除在发布包之外。
