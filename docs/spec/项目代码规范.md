# 项目代码规范

## 注释

- 说明正文和代码注释使用中文。代码标识符使用英文，API 名称、字段名及通用缩写保留原文。
- 类的说明应写清职责、适用范围和模块边界。函数与方法的说明应覆盖用途、参数、返回值及调用方需要了解的异常或特殊行为。
- 类的每个字段都应有独立注释，尤其是实体类。说明字段的业务含义，并在有需要时写清标识的归属、值的单位、默认值或为空的含义。新增或修改字段时同步更新注释。
- 在方法内的关键代码块旁用中文注释说明处理原因、触发条件和结果。外部数据格式差异、配置优先级、状态转换、失败恢复和持久化等细节应写到足以让评审者理解实现取舍。测试注释说明用例意图和容易误读的数据，行为变化时同步更新注释。

Python 的文档字符串格式、包文件和测试执行方式见 [Python 代码规范](Python代码规范.md)。

## 模块与实现

- 按[系统架构划分](系统架构划分.md)分配职责。相关逻辑保留在拥有该职责的模块内，跨模块通过公开接口和明确的数据类型调用。第三方 SDK、协议和格式转换细节由接入模块封装。
- 保持依赖方向清晰，避免循环依赖。优先复用现有契约与实现，在确有多个实现或需要隔离外部依赖时抽象接口。
- 保持类与方法职责集中，使用领域术语命名。外部调用、文件写入及失败恢复应有清晰边界，调用方可以判断结果是否完整。
- 按实际需要创建文件和目录，等有代码、配置、文档或测试内容时再建。仅为占位的空文件或空目录无需加入项目。

## 单元测试

- 单元测试集中在所属一级模块的 `test/` 下，沿用被测源码的相对路径。例如 `integration/fetcher/bilibili/client.py` 对应 `integration/test/fetcher/bilibili/test_client.py`。
- 测试文件按可验证的职责组织，相关用例可以放在同一文件。模拟网络和第三方服务，文件测试使用临时目录。真实服务验证与跨模块流程测试在有实际需求时独立运行。
